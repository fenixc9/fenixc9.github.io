零知识证明与 zk-SNARK：从阿里巴巴洞穴到 Tornado Cash

零知识证明（Zero-Knowledge Proof, ZKP）解决的是现代数字系统里一对天然的矛盾：验证者想要正确性保证，证明者不想泄露敏感输入。没有 ZKP 时，系统往往只能二选一——要么公开一切换取可验证，要么隐藏一切要求别人信任你。zk-SNARK 给出了第三条路：不泄露数据的前提下证明正确性。

本文从零知识证明的基础概念讲起，拆解 zk-SNARK 的五步编译管线，配以简化伪代码，最后落到它的标志性应用——Tornado Cash 混币协议——以及 Groth16 可信设置的取舍。

一、零知识证明：证明你知道秘密，却不泄露它

一个零知识证明必须满足三个性质：

  1. 完备性（Completeness）：陈述为真时，诚实验证者一定会被说服；
  2. 可靠性（Soundness）：陈述为假时，作弊者几乎不可能骗过验证者；
  3. 零知识性（Zero-knowledge）：验证者除了”陈述为真”之外一无所获。

经典例子是阿里巴巴洞穴：Peggy 知道环形洞穴中魔法门的口令，她随机走 A 或 B 路进去，Victor 在洞外随机喊一条路径让她出来。如果 Peggy 真知道口令，总能从指定路径出来；如果不知道，每次只有 50% 概率蒙对。重复 20 轮后，蒙对概率降至百万分之一。Victor 由此确信 Peggy 知道口令——却自始至终不知道口令本身。

注意两点：其一，这是概率性证明而非数学意义上的确定性证明，但作弊概率可以压到可忽略；其二，交互式证明的转录不可传递——第三方看到录像只会认为是伪造的，这恰恰是零知识性的一部分。

二、zk-SNARK 名字里的五个字母

缩写 含义 说明
Zero-knowledge 零知识 不泄露秘密
Succinct 简洁 证明极小（约 200 字节），验证毫秒级
Non-interactive 非交互 证明者发一条消息即可，无需来回对话
ARgument 论证 安全性依赖计算假设，而非信息论保证
Knowledge 知识 证明”知道秘密输入 w”

形式化地说，zk-SNARK 让你证明：“我存在私有输入 w，使得公开计算 C(x, w) = 1”。其中 x 是公开输入，w 是私密见证（witness），C 是程序或电路。

它的力量来自一条编译管线：

程序 → 算术电路 → R1CS → QAP → 密码学证明

三、五步编译管线

第 1 步：算术电路——把计算变成代数

zk-SNARK 不能直接理解普通程序（分支、循环、内存），需要先把计算转化为有限域上的算术电路——由加法门、乘法门、常数乘法门组成的无环图。比如要证明”我知道 x, y, z 满足 x·y + z = 35“（公开输出 out=35，私有输入 x=3, y=10, z=5）：

t1 = x * y
t2 = t1 + z
断言 t2 = out

第 2 步：R1CS——约束系统

把电路的每个门变成一条秩 1 约束，形如 (A_i·s) × (B_i·s) = (C_i·s)，其中 s 是包含所有变量和中间量的向量。上例产生 3 条约束：

约束 1:  x           · y           = t1        （乘法门）
约束 2:  (t1 + z)    · 1           = t2        （加法写成 ×1）
约束 3:  t2          · 1           = out       （等式检查）

加法之所以写成 ×1，是因为 R1CS 只支持一个乘法门——这就是”秩 1”（Rank-1）的含义。这一步把”计算正确性”变成了一组可代数检验的等式。

第 3 步：QAP——所有约束压缩成一个多项式整除性检查

这是整个体系最精妙的一步。对每个变量，用拉格朗日插值生成多项式族 u_j(X), v_j(X), w_j(X)，使它们在点 X=1,2,…,m 处的取值正好等于各约束行中的系数。对某个具体赋值 s，定义 U(X)、V(X)、W(X)。如果所有约束都成立，多项式 U(X)·V(X) − W(X) 在 X=1..m 处全为零——即它必须被目标多项式 t(X) = (X−1)(X−2)...(X−m) 整除：

U(X) · V(X) = W(X) + H(X) · t(X)

一条整除性陈述等价于满足全部 R1CS 约束——数百万个门的检查被压缩成了一个代数事实。

第 4 步：椭圆曲线编码 + 双线性配对——隐藏但仍可验证

问题来了：如果直接公开 U(τ), V(τ) 等域值，会泄露 witness。解法是把域元素藏进椭圆曲线群元素：

  • 编码 [a]₁ = a·g₁。由于离散对数难题，看到 [a]₁ 无法还原 a；但线性关系仍然保持：[a+b]₁ = [a]₁ + [b]₁；
  • 双线性配对 e: G₁ × G₂ → Gᴛ 满足 e(a·g, b·g) = (a·b)·g——这让验证者可以在隐藏的标量上检查乘法关系（如 U(τ)·V(τ) 与 W(τ)+H(τ)·t(τ) 的相等性），却看不到任何标量本身。

第 5 步：随机盲化——零知识性的来源

仅有编码还不够：证明元素是 witness 的线性组合，仍可能泄露信息。现代 zk-SNARK 给证明元素加入随机盲化因子，同一 witness 因此可以生成多个不可关联的证明，编码本身不泄露 witness 的任何信息。

四、伪代码

交互式零知识证明（Schnorr 识别协议）

# 公开参数：大素数 p、生成元 g；Peggy 知道秘密 x，公开 y = g^x mod p

# ---------- Peggy（证明者）----------
r = random()                        # 随机盲化因子，每次证明都换新的
C = pow(g, r, p)                    # 承诺：C = g^r
send(C)

# ---------- Victor（验证者）----------
challenge = random_choice(["reveal_r", "reveal_x_plus_r"])   # 随机二选一
send(challenge)

# ---------- Peggy 应答 ----------
if challenge == "reveal_r":
    send(r)
else:
    send((x + r) % (p - 1))

# ---------- Victor 验证 ----------
if challenge == "reveal_r":
    assert C == pow(g, r, p)
else:
    assert (C * y) % p == pow(g, x + r, p)   # g^r · g^x = g^(x+r)

# 重复 N 轮 → 作弊概率 2^(-N)；Victor 始终不知道 x

Schnorr 签名（Fiat–Shamir 非交互化）

# ---------- Peggy 签名消息 m ----------
r = random()
C = pow(g, r, p)                          # 承诺
e = H(C, m) % (p - 1)                     # Fiat-Shamir：挑战 = 哈希(承诺, 消息)
s = (r + e * x) % (p - 1)
signature = (C, s)                        # 发给任何人

# ---------- 任何人验证 ----------
assert pow(g, s, p) == (C * pow(y, e, p)) % p

把”验证者随机挑战”换成”哈希(承诺, 消息)”，就不再需要交互——但签名可公开传递、绑定身份，零知识性让位于公开可验证性。

zk-SNARK 管线（Groth16 概念版）

# ---- 第 3 步之后的密码学部分 ----

# ---- 可信设置（生成有毒废料 τ）----
tau = random()                            # 用完必须销毁，否则任何人可伪造证明
pk = encodings_of([u_j(tau), v_j(tau), w_j(tau)], t(tau), blinding_bases)
vk = minimal_verification_key()

# ---- Prove（在 τ 处求值 + 盲化）----
# 不需要知道 τ 本身——用 pk 中 u_j(τ) 的编码做同态线性组合：
U = sum(s_j * enc(u_j(tau)) for j in vars)     # 指数中运算，看不到 s_j
V = sum(s_j * enc(v_j(tau)) for j in vars)
W = sum(s_j * enc(w_j(tau)) for j in vars)
H = enc(quotient) + random_blinding
r1, r2 = random(), random()               # 盲化因子 → 零知识性来源
pi = (A, B, C)                            # Groth16：证明只有三个群元素

# ---- Verify（一次配对方程，恒定时间）----
assert pairing_check(pi, vk, public_inputs=[out])

Tornado Cash 取款电路

# ============ 公开输入（链上可见）============
#   root          : 资金池 Merkle 树根（合约存储）
#   nullifier_hash: 作废符哈希（合约标记已花费）
#   recipient     : 提款地址
# ============ 私有 witness（本地，不上链）============
#   secret        : note 里的秘密值
#   merkle_path   : 从叶子到根的路径（兄弟节点 + 方向）
#   nullifier     : nullifier 原像

def prove(secret, merkle_path, nullifier, root, nullifier_hash):
    commitment = PedersenHash(secret)                 # 存款时已提交的承诺
    assert merkle_verify(commitment, merkle_path, root)   # 约束族 1：成员性
    assert Hash(nullifier) == nullifier_hash          # 约束族 2：作废符绑定
    return groth16_prove(circuit, [secret, merkle_path, nullifier])
    # ← 只有证明 π 上链

def on_chain_withdraw(pi, root, nullifier_hash, recipient):
    assert nullifier_hash not in spent_list           # 防双花（合约检查）
    assert groth16_verify(vk, [root, nullifier_hash, recipient], pi)
    spent_list.add(nullifier_hash)
    transfer(pool, recipient, FIXED_AMOUNT)           # 固定面额付款

观察者视角：只知道”树中某笔存款被取出”，无法把 nullifier_hash 与 commitment 配对（zk 证明保证），也无法关联到任何钱包身份。

五、Groth16 与可信设置

Groth16（2016 年）是 Tornado Cash 采用的构造，也是最有影响力的配对类 zk-SNARK：证明只有三个群元素，验证只需一次紧凑的配对方程。它的代价是可信设置：

  • Setup 时生成一个秘密点 τ（”有毒废料”，toxic waste），证明密钥里只含 τ 的密码学编码，证明者永远不知道 τ 本身；
  • 如果有人知道 τ，就能伪造证明——所以 τ 生成后必须销毁；
  • Groth16 的设置按电路定制，电路一改就要重新仪式。后续的 PLONK 改为通用设置（一次仪式适用所有电路），zk-STARK 则完全免设置。

Tornado Cash 的解法是公开的多方仪式（ceremony）：1000 多名志愿者依次贡献熵，只要至少一人诚实地销毁了自己的部分，τ 就无法被任何人重构。这也是 2024 年 11 月美国第五巡回上诉法院判决中引用的关键事实——“一旦智能合约变得不可变，就没人能收回对它的控制权”。

六、数字签名是退化的零知识证明吗

直觉上很接近：签名确实证明了”我知道私钥”而不泄露私钥。而且 Schnorr 识别协议在文献里就是诚实验证者零知识的知识证明（ZKPoK）——Schnorr 签名正是它经 Fiat–Shamir 变换后绑上消息的产物。

但标准数字签名不是严格的零知识证明，差别有三点：

维度 数字签名 零知识证明
可传递性 人人可验证、可转发、可保存（违反零知识性） 交互式转录不可传递
身份 暴露”是哪个 key”（可归属） 不暴露是哪个 witness
表达能力 只证”我知道 sk” 任意计算 C(x,w)=1

放到一根”匿名化程度”的轴上看就清晰了：数字签名（证明知识，暴露身份）→ 环签名（加匿名集，签名者藏在公钥组中，门罗币采用）→ zk-SNARK（加任意计算与完全零知识）。Tornado Cash 的取款证明恰好是两者的合体——证明知道某张 note 的秘密，但不暴露是哪张、也不经过任何钱包签名。若改用普通签名来证明 note 所有权，取款地址立刻与签名身份绑定，匿名性直接归零。

七、zk-SNARK vs zk-STARK

维度 zk-SNARK（Groth16） zk-STARK
可信设置 需要（按电路定制，有毒废料） 不需要（透明，公开随机性）
证明大小 极小（约 200 字节） 较大（数十到数百 KB）
验证速度 快（毫秒级） 快，但证明更大
底层假设 椭圆曲线离散对数（配对） 哈希函数（抗量子）
代表应用 Tornado Cash、Zcash StarkNet、可扩展 rollup

结语

zk-SNARK 的本质是一条五步编译管线：把计算变成算术电路 → 变成约束系统 → 插值压缩成一个多项式整除性检查 → 用椭圆曲线编码隐藏、用双线性配对验证 → 用随机盲化实现零知识。它同时解决了正确性可验证与隐私不泄露这两个矛盾需求，而 Tornado Cash 把这套机制用在 Merkle 树成员性证明上，实现了透明链上的强匿名性——围绕它的制裁与法律诉讼，也在过去几年里成为整个隐私技术行业的判例来源。
