SSH 除了端口转发还能做什么：连接复用、VPN、证书与受限入口

ssh -L、ssh -R 和 ssh -D 解决的是同一个问题：把一个端口接到另一端。SSH 还能复用已经建立的连接，承载三层网络，充当身份与签名系统，把登录入口收缩成只允许固定动作的 API。

这些能力适合不同场景。先判断需求属于哪一类，再选命令，比记住一堆参数更有用。

本文以 OpenSSH 8.9p1 的命令行为基准。除特别说明外，命令没有逐条实测。不同发行版和旧版本的行为可能不同。

1. 三类需求与对应手段

需求 主要手段 主要代价
减少重复握手 ControlMaster、ControlPersist 多条客户端复用一条 TCP，master 异常时要重连
运行时增删转发 ~C、ssh -O forward/cancel 需要已有 master 连接
全量网络接入 -w tun、sshuttle tun 需要两端 root，sshuttle 只覆盖 TCP 与 DNS
远程文件系统 sshfs 弱网要配重连与 keepalive
跳板与代理嵌套 -J、-W、ProxyCommand 受中间跳的转发策略限制
NAT 穿透 -R 加 autossh 或 systemd 暴露面由 GatewayPorts 决定
身份与签名 SSH CA、ssh-keygen -Y、FIDO2 需要额外的信任根和吊销策略
受限入口 authorized_keys 选项、ForceCommand、chroot SFTP 配置错误会让限制失效

后面按“通道、身份、执行入口”的顺序展开。文件传输和批量运维单独列出。

2. 复用连接，减少重复握手

SSH 每次登录都要完成 TCP 握手、密钥交换和认证。对 git、scp、kubectl 这类高频短连接，开销主要在这里。连接复用让后续客户端直接走已有的 master 连接。

Host *
  ControlMaster auto
  ControlPath ~/.ssh/cm-%r@%h:%p
  ControlPersist 10m

第一个连接成为 master。最后一个客户端退出后，master 再保留 10 分钟。ControlPath 的 socket 权限等价于私钥，应放在权限为 700 的目录中，不要放 /tmp。

master 存在时，可以在不重新登录的情况下管理转发：

ssh -O check  host
ssh -O forward -L 8080:localhost:80 host
ssh -O cancel -L 8080:localhost:80 host
ssh -O exit   host

-O forward 配合 -R 0:localhost:80 时，服务端动态分配端口，并把端口号打印到标准输出。这个行为适合脚本建立临时反穿。

已经处在交互会话里时，在行首输入 ~C 会进入 ssh> 提示符。此时可以直接追加 -L、-R、-D 转发，不必断开重连。其他常用转义如下：

  • ~# 列出当前转发；
  • ~& 把会话放到后台；
  • ~^Z 挂起；
  • ~. 断开；
  • ~R 请求 rekey。

3. 用 SSH 承载三层网络

tun 模式

ssh -w 0:0 -o Tunnel=point-to-point user@host

两端都需要 root。服务端要开 PermitTunnel yes。隧道建立后，还要在两端配置 tun 地址和路由。SSH 只负责把三层包送过去，不负责地址规划。这条命令能建立最小可用的三层隧道，但没有成熟 VPN 的密钥轮换、重放防护和运维能力。

sshuttle

sshuttle -r user@host 0/0 --dns

本地需要 sudo。远端只需要 Python，不要求 root，也不需要在远端创建 tun。sshuttle 接管本机的 TCP 连接和 DNS 请求，再经 SSH 转发。它适合临时把一台机器的流量带到远端网络。

限制是只处理 TCP 与 DNS。UDP 业务不会被代理，包括 QUIC、部分游戏和语音。

反向动态 SOCKS

-R 不带目标地址时，远端会变成一个 SOCKS 4/5 服务，把连接反向往本地发起：

ssh -R 1080 -N vps

这个命令需要较新的 OpenSSH，8.9 可用。它让 VPS 的 1080 端口成为进入你本地网络的入口。默认只监听回环。一旦服务端开启 GatewayPorts 并绑定公网地址，任何能访问该端口的人都能借你的机器出网。只应在可信环境短期使用，并用 PermitListen、防火墙和认证收口。

443 端口复用

只放行 443 的网络里，可以用 sslh 让 SSH 与 HTTPS 共用 443。sslh 按首包特征分流。这个做法用于绕过网络策略，是否合规取决于所在环境。

4. 传输文件与挂载目录

# 挂载远端目录；弱网要加重连和 keepalive
sshfs user@host:/data /mnt -o reconnect,ServerAliveInterval=15

# 保留权限搬运目录，不落中间文件
tar czf - dir | ssh host 'tar xzf - -C /dest'

# 远端磁盘镜像，本地压缩
ssh host 'dd if=/dev/sda bs=4M' | pv | gzip > disk.img.gz

# 增量同步；远端需要 sudo 时指定 rsync 路径
rsync -avz -e ssh src/ host:/dest/
rsync -avz --rsync-path="sudo rsync" src/ host:/dest/

# 两台互不相通的机器借本机中转
scp -3 host1:/path host2:/path

dd 对正在挂载并写入的磁盘做镜像，可能得到不一致的数据。生产环境应先做快照，或在只读、停机状态下操作。scp -3 的数据会经过本机，两台远端之间并不会直连。

数据库备份也常直接借 SSH 的 stdout：

ssh host 'mysqldump --single-transaction db' > dump.sql

这类用法不需要在远端安装 agent。注意把 stderr 与 stdout 分开，避免日志污染数据。

5. 跳板、穿透与协议嵌套

跳板链

ssh -J user@bastion1,user@bastion2 target

-J 等价于自动生成 ProxyCommand ssh -W %h:%p ...。它不把 agent 暴露给跳板机，通常比 -A 转发 agent 更安全。配置里可以用 ProxyJump none 覆盖默认跳板。

把 stdio 接到任意 TCP

ssh -W db.internal:5432 bastion

-W 把标准输入输出直接接到目标 TCP。它可以当通用连接器，也是 ProxyCommand 的常用写法。-W 隐含 -N -T，不执行远程命令。

ProxyCommand 组合

# SSH 先走 HTTP 代理
ProxyCommand nc -X connect -x 127.0.0.1:8080 %h %p

# 通过 Tor 访问 .onion 主机
ProxyCommand nc -X 5 -x 127.0.0.1:9050 %h %p

# 通过 Cloudflare Tunnel 暴露的 SSH 入口
ProxyCommand cloudflared access ssh --hostname %h

macOS 自带的 nc 不支持 -X，可以改用 ncat。这套组合的价值在于：只要有一层承载网络能出网，SSH 就能被带出去。wstunnel、chisel 属于同一类工具。

反向隧道与自动重连

autossh -M 0 -N \
  -o ServerAliveInterval=30 -o ServerAliveCountMax=3 \
  -o ExitOnForwardFailure=yes \
  -R 2222:localhost:22 vps

-M 0 关闭 autossh 自己的 echo 端口，改用 SSH keepalive 判断存活。ExitOnForwardFailure 保证端口绑定失败时直接退出，交给 systemd 重启。没有这个选项时，进程可能保持连接，却没有建立转发。

生产环境应配合 Restart=always、RestartSec 和日志告警。

Unix socket 转发

-L 和 -R 的目标可以是 Unix socket。这个能力适合容器和本地守护进程：

ssh -L /tmp/docker.sock:/var/run/docker.sock host
DOCKER_HOST=unix:///tmp/docker.sock docker ps

# Docker CLI 原生支持把 SSH 当传输层
DOCKER_HOST=ssh://user@host docker ps

本地 socket 已存在时，绑定会失败。加 -o StreamLocalBindUnlink=yes 让 SSH 先删除旧 socket。同一方法可以转发 MySQL socket 和 gpg-agent。

子系统

ssh -s host netconf

-s 请求的是 SSH 子系统，不是 shell。NETCONF（RFC 6242）规定用 SSH 子系统承载。SFTP 也走子系统。自定义子系统需要在服务端 Subsystem 中声明。

6. 用 SSH 管理身份

自建 SSH CA

不再把公钥分发到每台机器，而是让服务端信任一个 CA，由 CA 签发短时效证书：

ssh-keygen -t ed25519 -f ca
ssh-keygen -s ca -I alice -n alice,deploy -V +8h alice.pub

服务端配置 TrustedUserCAKeys /etc/ssh/ca.pub。客户端可以在 known_hosts 写 @cert-authority *.example.com ssh-ed25519 AAAA...，用同一套机制信任主机证书。

-n 是 principals，需要与登录用户名或 AuthorizedPrincipalsFile 匹配。证书自带有效期，适合临时授权。吊销依赖 RevokedKeys 或短 TTL，不要靠删除 authorized_keys。

用 SSH key 签名

ssh-keygen -Y sign -f ~/.ssh/id_ed25519 -n file doc.txt
ssh-keygen -Y verify -f allowed_signers -I me -n file -s doc.txt.sig < doc.txt

Git 2.34 及以后可以直接用 SSH key 签名提交，省去 GPG 的密钥管理：

git config gpg.format ssh
git config user.signingkey ~/.ssh/id_ed25519.pub
git commit -S

FIDO2 硬件密钥用 ssh-keygen -t ed25519-sk。私钥留在硬件内，适合高价值环境。

agent 转发的风险

-A 把 agent 转发到远端。会话期间，远端 root 可以使用你的私钥。远端被攻破时，攻击者能通过 agent socket 以你的身份登录其他机器。

优先用 -J 跳板。必须转发时，用 ssh-add -c 要求逐次确认。不需要时用 ssh -a 显式关闭。

7. 把登录入口收缩成受限 API

authorized_keys 的前缀选项可以把一个 key 限制成只能做一件事：

from="10.0.0.0/8",command="/usr/local/bin/deploy.sh",no-pty,no-agent-forwarding,no-port-forwarding,expiry-time="20261231" ssh-ed25519 AAAA...
  • from= 限制来源地址，支持 CIDR 与通配；
  • command= 强制命令，原命令放在 $SSH_ORIGINAL_COMMAND；
  • no-pty、no-agent-forwarding、no-port-forwarding 关闭不需要的能力；
  • expiry-time 给 key 设置过期时间。

如果需要保留转发，不要写 no-port-forwarding。改用 permitopen 只允许指定的 -L 目标，用 permitlisten 限制 -R 的监听地址。两者是替代关系。同时写 no-port-forwarding 和 permitopen 会让转发全部失效。

配合一个只认白名单命令的脚本，就得到一个用 SSH 传输的极简 RPC：

#!/bin/sh
case "$SSH_ORIGINAL_COMMAND" in
  backup) /usr/local/bin/backup.sh ;;
  *) echo "denied" >&2; exit 1 ;;
esac

调用方执行 ssh -i deploy_key host backup。这个 key 拿不到 shell，也无法开隧道。

SFTP 投递箱

Match Group sftponly
  ChrootDirectory /srv/sftp/%u
  ForceCommand internal-sftp
  AllowTcpForwarding no
  X11Forwarding no

ChrootDirectory 及其上级必须由 root 所有，组和其他用户不可写。否则 sshd 会拒绝登录。这是“只收文件、不给 shell”的标准做法。

从外部系统拉公钥与强制双因子

AuthorizedKeysCommand /usr/local/bin/fetch-keys %u
AuthorizedKeysCommandUser nobody

# 公钥之后再走一次键盘交互，通常是 TOTP
AuthenticationMethods publickey,keyboard-interactive

AuthorizedKeysCommand 适合从 GitHub、LDAP 或内部 IAM 同步公钥。它指向的脚本必须由 root 所有，普通用户不可改写。

AuthenticationMethods 要求公钥认证之后再走一次键盘交互。单把私钥泄露不足以登录。这个配置需要服务端已经接好 TOTP 或 PAM。

8. 批量运维与排障

把 config 当主机清单

Host *.internal
  User ops
  ProxyJump bastion

Host app-*
  RemoteCommand tmux new -A -s main
  RequestTTY yes

Match exec 可以做条件匹配。下面的配置只在直连 22 端口失败时走跳板：

Match host *.internal exec "! nc -z -w1 %h 22"
  ProxyJump bastion

exec 在每次连接时本地执行。条件复杂会拖慢所有连接。不要把有副作用的命令放进去。

查看实际生效配置

ssh -G host | grep -E 'proxyjump|user|port|identityfile'
ssh -Q key
ssh -Q cipher
sshd -T | grep -i forward

ssh -G 输出合并默认值、系统配置和用户配置后的结果。排查“为什么没走跳板”或“为什么用了错 key”时，它比 -v 更快。

ssh -Q key 和 ssh -Q cipher 列出本机支持的算法。sshd -T 输出服务端实际配置，需要 root。ssh-audit host 可以检查服务端算法和已知弱配置。

脚本与批量

# -n 防止 ssh 吃掉 while 循环的 stdin
while read -r h; do
  ssh -n -o BatchMode=yes -o ConnectTimeout=5 "$h" 'uptime' &
done < hosts.txt
wait

# 远程执行本地脚本；参数会经远端 shell 拼接
ssh host bash -s -- "$arg1" "$arg2" < local.sh

脚本里建议同时设置 BatchMode=yes、ConnectTimeout、ServerAliveInterval 和 StrictHostKeyChecking=accept-new。

批量主机交给 pdsh、clush、ansible 或 parallel -S ssh。不要手写没有超时和并发控制的循环。

远程端口连通性可以用 bash 的 /dev/tcp 判断：

ssh host 'timeout 3 bash -c "</dev/tcp/db.internal/5432" && echo ok'

这个命令验证的是“从远端看目标是否可达”。它和从本机执行 nc 的结果可能不同，适合定位网络策略问题。

9. 边界与安全清单

  • 不转发 UDP：-D 的 SOCKS5 不支持 UDP ASSOCIATE。-L 和 -R 只做 TCP 与 Unix socket。UDP 只能走 -w 的 tun 隧道，或改用 WireGuard 之类的方案。
  • 吞吐受限：单条 TCP 加加密开销，大流量和弱网表现一般。交互式远程可以用 mosh 改善 roaming 与延迟。
  • 反穿端口是暴露面：-R 加 GatewayPorts 会把内网服务放到公网。服务端用 PermitOpen、PermitListen、AllowTcpForwarding no 做白名单，并监控异常监听。
  • 不要长期关闭主机密钥校验：StrictHostKeyChecking=no 和 UserKnownHostsFile=/dev/null 只适合一次性环境。
  • 旧算法只对老设备开口子：ssh-rsa、diffie-hellman-group1-sha1 等应在 Host 级别局部启用，不要写进全局配置。
  • 隧道也是外传通道：反向隧道既能做 NAT 穿透，也能做后门。生产环境需要证书、白名单、会话审计和流量监控，不能只靠一把共享私钥。

10. 选择顺序

  1. 只需要执行一个固定动作：用 command= 或 ForceCommand，不要给 shell。
  2. 需要一个 TCP 端口：用 -L 或 -R。跨多跳时加 -J 或 ProxyCommand。
  3. 需要整个网络：先试 sshuttle。需要 UDP 或稳定长期组网时，改用 WireGuard。
  4. 需要管理大量主机和人员：上 SSH CA 和短期证书，再配 AuthorizedKeysCommand 与双因子。
  5. 需要审计和最小权限：限制来源、命令、转发目标和有效期。把 key 当成一次性凭据，不要当永久凭证。

SSH 的扩展能力大多来自同一个基础：一条经过认证的加密连接。连接复用、转发、子系统、证书和受限命令都建立在这条连接上。理解这一点，比收集命令片段更有用。
