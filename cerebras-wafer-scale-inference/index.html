一片晶圆做一颗芯片：Cerebras 深度调研

Cerebras 是把**整片 300mm 晶圆做成一颗芯片（Wafer-Scale Engine, WSE）**的公司：用”面积换带宽、用片上 SRAM 换内存墙”的方式，在大模型推理（尤其 decode 阶段）做出远超 GPU 云的 token 生成速度，同时也在训练侧用晶圆集群挑战 NVIDIA。

本文核心事实来自 2019–2025 年中的公开资料（官方规格页、Cerebras Inference 发布、S-1 招股书、行业报道）。环境日期为 2026 年 9 月，凡涉及”最新一代硬件 / IPO 最终状态 / 最新推理记录”的判断，文中以 ⚠️ 待核实 标出，请以官方最新发布为准。

一、与 GPU 路线的根本分歧

NVIDIA 的路线是：小 die + 先进封装 + HBM + NVLink + 大规模互联，靠系统级扩展取胜。Cerebras 的路线是：超大 die（整片晶圆）+ 片上海量 SRAM + 片上互联，靠”把东西放在离计算最近的地方”取胜。这是两条不同的物理路径，不是简单的”更快/更慢”。

Cerebras 的技术护城河不是”算力峰值”，而是片上内存带宽 + 低延迟互联。它的核心叙事是绕开 GPU 推理里最致命的 memory-bandwidth-bound 瓶颈：把权重和 KV cache 尽量留在片上统一 SRAM 里，或通过极高带宽的权重流式（Weight Streaming）喂进来。这使得它在 decode 单 token 生成上极具优势。

它在”推理服务”这一细分赛道已经证明了产品力——Llama、DeepSeek-R1、Qwen3、GPT-OSS 等模型上的数千 token/s 记录是真实的商业卖点；但片上 SRAM 容量有限、成本高、CUDA 生态壁垒，使它难以成为通用训练/推理的默认选择，更可能长期占据”超低延迟、高单价”的高端推理市场。当前最前沿硬件是 WSE-3 / CS-3（5nm、4 万亿晶体管、44GB 片上 SRAM、125 PFLOPS）。⚠️ 是否已有 WSE-4 / CS-4 发布需核实；但即便有新一代，其架构逻辑与约束与 WSE-3 一脉相承，本文的原理分析仍然成立。

2.2 CS-3 与配套系统

CS-3 是 WSE-3 的系统形态：单机为水冷、机架级设备。官方称最多可将 2048 台 CS-3 组成一个集群，聚合算力达 ~256 exaFLOPS；配合 MemoryX + SwarmX，可训练参数规模远超单芯片 SRAM 容量的模型。

WSE 的”短板”是片上容量有限，Cerebras 用两套外部系统补足：

系统 作用 关键参数（官方口径，⚠️ 数字随代际变化）
MemoryX 片外参数存储，做”权重流式”（Weight Streaming） 容量可达 PB 级（如 ~1.2 PB），带宽数十 TB/s
SwarmX 训练时把参数/梯度广播到集群各 CS 系统 极高扇出带宽，支撑大规模数据并行

权重流式是理解 Cerebras 的关键补充：模型权重不完全驻留片上，而是从 MemoryX 以高带宽流式注入 WSE，边流边算。这让”训练万亿参数模型”成为可能，但推理时的低延迟优势会随模型超出片容量而衰减。

2.3 CS-3 与主流 GPU 系统对比

维度 NVIDIA GPU 系统（如 H100/H200/B200 集群） Cerebras CS-3
基本形态 多 die + HBM + NVLink/网络 整片晶圆单芯片
权重/KV 位置 主要在 HBM，片上 cache 较小 大片 SRAM（44GB）+ 流式扩展
内存带宽 HBM ~TB/s 级（单卡） 片上 ~21 PB/s
访问延迟 HBM 较高 片上 SRAM 极低

优势 生态成熟、容量大、训练/推理通用、性价比 超低延迟、超高单用户 token/s、带宽极高
劣势 decode 受 HBM 带宽限制 成本/功耗高、片上容量有限、生态小

三、推理为什么快

3.1 标志性记录

Cerebras 的推理云（Cerebras Inference）以”世界最快”为定位，公开了一系列刷新记录的吞吐数据（数值为量级参考，最新值需以官网为准）：

模型 吞吐（tokens/s） 备注
Llama 3.1 8B ~1,800–2,100 2024 年发布时的旗舰记录
Llama 3.1 70B ~450（早期）→ 后续提升 单用户速度远超 GPU 云
Llama 3.1 405B ~969 大模型仍保持高速度
Llama 3.3 70B ~2,200 70B 级刷新记录
DeepSeek-R1 671B ~1,500 对比 GPU 云宣称约 57x 更快
Qwen3 235B ~1,400 2025 年 MoE 模型
GPT-OSS-120B ~3,000 2025-08 OpenAI 开放模型，宣称最快推理

关键点：这里”数千 token/s”是单请求/低并发下的单用户速度，这正是 Cerebras 架构最强的地方。GPU 云在高 batch 下也能做到高聚合吞吐，但单用户速度会显著下降。

3.2 decode 阶段为什么特别快

大模型推理分两阶段：

  • Prefill（处理 prompt）：计算密集（compute-bound），GPU 也很强；
  • Decode（逐 token 生成）：数据搬运密集（memory-bandwidth-bound）——每生成一个 token 要读大量权重 + KV cache。

粗略模型：

每 token 时间 ≈ 读取权重/KV 的时间 + 计算时间

在 GPU 上，权重/KV 大多在 HBM，HBM 带宽虽高但远不及 SRAM；且跨卡还要走 NVLink。Cerebras 则：

  1. 权重/KV 尽量放片上 SRAM（44GB），带宽 ~21 PB/s；
  2. 片内 NoC 延迟极低，模型切分后主要在同片内流动；
  3. 900,000 核 + 编译器数据流调度，把层/attention/batch/token 细粒度并行。

于是”等数据”的时间被大幅压缩，token 生成速度自然上去。加上小模型（8B 级）首 token 延迟可到亚 200ms 级（大模型因权重流式/初始化会更高），Cerebras 的卖点是首 token 快 + 后续 token 更快，适合实时对话、代码补全、agent 循环等对延迟极敏感的场景。

训练侧则主要借助与 G42 合作的 Condor Galaxy 系列超算（CG-1/CG-2/CG-3）做验证，官方宣称可训练万亿参数级模型。⚠️ 训练市场的实际份额远小于推理，NVIDIA 仍是训练绝对主导。

四、原理架构

4.1 晶圆级集成：不切割的晶圆

传统做法是把晶圆切成许多小 die 再封装，Cerebras 反过来：

  • 不切割，直接在整片晶圆上布线，让相邻区域通过跨 reticle（光罩）连线互通；
  • 整片晶圆必然有缺陷，用硬件冗余 + 冗余核/列绕行处理良率：坏掉的核被绕过，整体仍可工作；
  • 结果是 46,225 mm² 的单片计算体，核数、SRAM、互联全部在同一芯片内。

代价是功耗巨大、散热需水冷、制造与封装成本极高、供应链门槛高。

4.2 内存层次：SRAM 即主存

层级 GPU Cerebras
主存 HBM（容量大、带宽 TB/s 级、延迟高） 片上 SRAM（容量 44GB、带宽 PB/s 级、延迟低）
扩展 多卡 HBM + NVLink MemoryX 权重流式（PB 级、数十 TB/s）
cache L2 较小 无独立”cache”，SRAM 即主存，分布式与核绑定

核心思想：把带宽和延迟做到极致，用容量换速度。

4.3 片上互联与执行模型

每个核与相邻核组成 2D mesh，数据以 packet 在 fabric 上路由，带宽达 Pb/s 量级，延迟远低于跨卡 NVLink/网络——“张量并行/流水并行”发生在片内，避免了 GPU 集群常见的跨节点通信与同步开销。

执行模型上，Cerebras 采用偏**静态数据流（dataflow）**的方式：编译期把计算图映射到具体核与片上路由，运行时按计划流动。好处是数据搬运可被编译器全局优化，减少不必要的读写；代价是灵活性不如 GPU，模型/算子需适配其软件栈。软件栈以 CSL（Cerebras Software Language，类 C 的底层语言） + graph compiler 为核心，把 PyTorch/JAX 模型切分、布局到片上 SRAM、安排权重与 KV cache、做 continuous batching。与 CUDA 生态相比工具链成熟度仍是短板，但推理 API 层已相对友好。

4.4 训练 vs 推理的取舍

场景 是否吃片上容量 Cerebras 优势
小模型推理（≤ 片容量） 权重可全驻留 极强（低延迟、高 token/s）
大模型推理（> 片容量） 需权重流式 仍强，但受外部带宽牵制
训练（万亿参数） 依赖 MemoryX/SwarmX 有竞争力，但生态/成本劣势明显

Cerebras 的甜点区是”模型能装进片内或接近片内 + 对延迟极敏感”的推理。

五、Cerebras vs Groq：两条 SRAM 路线

两家都反 HBM、都用 SRAM、都走”编译器驱动的静态数据流”，但扩展哲学完全相反：

  • Cerebras = Scale-Up（把一颗芯片做大）：不切割晶圆，把整片做成一颗 46,225 mm² 的巨芯片，靠片内 NoC 把带宽和容量一次性拉满。
  • Groq = Scale-Out（把很多小芯片拼成逻辑大芯片）：用常规可量产 die，靠确定性以太网把几百张 LPU 拼成一个”逻辑巨芯片”，编译期把时钟周期全部排死。

5.1 逐项对比

维度 Cerebras（WSE-3 / CS-3） Groq（LPU）
芯片形态 整片晶圆单芯片 标准可量产 die，单卡较小
制程 5nm 较成熟制程（14nm 起）
片上 SRAM 44 GB ~230 MB/卡（量级）
片上带宽 ~21 PB/s ~80 TB/s 量级/卡
核/算力 900,000 核，~125 PFLOPS 大量确定性 VLIW/MAC 单元
执行模型 静态数据流 + 编译器布局到核与路由 完全确定性 dataflow，编译期排定时钟，无 cache/仲裁/动态调度
容量策略 片内 44GB + MemoryX 权重流式（PB 级） 单卡装不下大模型，必须靠数百卡拆分
扩展方式 片内 NoC 为主，跨系统靠 SwarmX 确定性网络把多卡拼成逻辑大芯片
延迟特性 单芯片内极低延迟 延迟可预测、抖动小（确定性是核心卖点）
制造/成本 极高（整片晶圆、水冷、良率冗余） 相对常规 die，但需大量卡堆叠
训练能力 可训练（MemoryX/SwarmX） 主打推理
定位 训练 + 推理，推理主打”最快” 纯推理，主打”确定性与低延迟”

5.2 本质差异

  1. 容量 vs 良率：Cerebras 把容量押在”单片巨芯片”上，代价是制造良率与成本；Groq 把容量押在”多卡堆叠”上，代价是跨卡拆分与通信，但换来可量产、低成本、成熟制程。
  2. 延迟 vs 确定性：Cerebras 追求绝对低延迟/高吞吐；Groq 追求延迟可预测（低抖动），这对实时系统、agent 循环、金融/工业场景很关键。
  3. 带宽来源：Cerebras 的带宽来自片内 SRAM + NoC；Groq 的带宽来自片上 SRAM + 确定性网络。两者都能绕开 HBM 的带宽墙，但瓶颈位置不同——Cerebras 受片容量限制，Groq 受卡数与网络拆分限制。
  4. 共同点：都吃”编译器 + 静态数据流“这碗饭——因为 SRAM 容量小、必须精细复用，编译器质量直接决定性能上限。这也是它们与 GPU”动态调度 + HBM”路线的根本分野。

一句话：Cerebras 用制造换容量，Groq 用网络换容量；前者赢在单片带宽，后者赢在可量产与确定性。

六、国内 SRAM 路线厂商

国内没有广为人知的”中国版 Cerebras”（晶圆级商业化），但 SRAM 路线有两个活跃分支：数据流/可重构 和 SRAM 存算一体（CIM）。（⚠️ 产品与融资细节需核实）

公司 路线 用 SRAM？ 对标 备注
清微智能（Tsingmicro） 可重构数据流 RPU 重片上 SRAM 最接近 Groq/SambaNova 清华系，”软件定义硬件”
亿铸科技 SRAM 存算一体 ✅ 存算一体大模型推理 这批里最直接打大模型推理场景
后摩智能（Houmo.AI） SRAM 存算一体 ✅ 边缘/智驾 主打高能效
苹芯科技（Pimchip） SRAM 存算一体 ✅ 边缘 AI
九天睿芯（Reexen） SRAM 存算一体 ✅ 传感/边缘
知存科技（Witmem） NOR Flash 存算一体 ❌（Flash） 存算一体 需与 SRAM 路线区分
晶圆级集成 高校/研究所为主 — Cerebras 清华/中科院/北大等有原型，无成熟商业公司

路线差异：

  • 数据流/可重构（清微智能等）：思路最接近 Groq——把计算图编译期映射到片上，重 SRAM、轻 HBM，追求能效与确定性。但片上 SRAM 规模远小于 Cerebras，也不走晶圆级。
  • SRAM 存算一体（亿铸/后摩/苹芯/九天睿芯等）：在 SRAM 阵列内直接做乘加，省掉”权重搬运”这一步，是绕过内存墙的另一种解法；优势在能效与成熟制程可用，劣势是精度/工艺/规模化难。
  • 晶圆级：国内几乎只有学术原型，原因与 Cerebras 的门槛一致——良率冗余、水冷、封装、供应链，且没有一家有 Cerebras 那样的资本与客户规模来跑通。

一个关键背景：出口管制反而利好 SRAM/存算一体路线。国产高端 HBM、先进制程、高端 GPU 均受出口管制影响，这使国内团队更有动力绕开”先进制程 + HBM + 多卡互联”这条被卡脖子的主流路线，转向成熟制程 + SRAM 存算一体（不依赖先进 HBM）、3D 堆叠/近存计算（用封装而非制程换带宽）、数据流/可重构架构（用编译器换面积）。所以国内 SRAM 路线的动力，一部分是技术，一部分是供应链安全——这与 Cerebras/Groq 在美国”挑战 NVIDIA”的动机不同。

七、成本：”更快但更贵的推理”

推理成本必须区分两个维度——① 云 API 单价（$/1M tokens） 与 ② 自建系统 TCO（$/有效 token）。前者是用户看到的价，后者是厂商的账。⚠️ 下列价格均为公开资料中的量级参考，2025H2–2026 变动频繁，务必以官网最新价格为准。

  • GPU 云单价通常最低/最有弹性，因为有规模、有缓存折扣、有竞价实例。

决定成本的关键变量：Batch/并发（SRAM 路线在低并发单请求下速度优势最大，GPU 在高 batch 下吞吐/成本反超）、输入输出比（推理贵在输出，输出越长 SRAM 路线的”快”越值钱）、模型大小 vs 片容量（装进 SRAM 时成本效率最高，超出后边际成本上升）、量化与 KV cache 管理、利用率（再快的芯片，闲置就是浪费）。

7.3 成本与速度的排序

成本排序（同模型、单位 token）：  GPU 云  <  Groq  <  Cerebras
速度排序（单用户 token/s）：       Cerebras  >  Groq  >  GPU 云
  • 要便宜、要弹性、要生态：选 GPU 云；
  • 要极致速度、愿为延迟付溢价：选 Cerebras；
  • 要可预测低抖动、成本又比 Cerebras 友好：选 Groq；
  • 国产替代：SRAM 存算一体路线理论上能效更优、可绕开 HBM 管制，但规模与生态尚未到能压成本的阶段，短期更多是能效叙事而非价格优势。

一句话：SRAM 路线不是”更便宜的推理”，而是”更快但更贵的推理“。

八、前景与核心判断

机会：agent、实时对话、代码补全等对 TTFT/TPOT 极敏感的推理需求爆发；晶圆级 + 片上 SRAM 是少数能真正绕开内存墙的路径，短期难被复制；G42 等国家级/大企业订单提供稳定收入；每次刷新 token/s 记录都是营销。

挑战：NVIDIA 生态壁垒（CUDA、模型适配、人才、供应链）；44GB 片上 SRAM 对超大模型不够，需流式，削弱延迟优势；晶圆级芯片制造、水冷、机架成本高，单位经济学未必优于 GPU 云；供应与部署门槛高，无法像 GPU 一样由普通云厂商大规模铺开；Groq、d-Matrix、云厂商自研 ASIC 分食推理市场；G42 关系曾引发美国 CFIUS 审查，影响 IPO 与海外扩张。

核心判断：

  • 短期（1–2 年）：继续在”最快推理”叙事上领先，重点客户是高价值、延迟敏感的推理场景；训练侧更多是标杆项目而非主流。
  • 中期（3–5 年）：胜负取决于能否把软件生态做厚 + 能否用新一代硬件提升片内容量/降低成本。若生态补齐，可从”最快”走向”最实用”。
  • 长期：晶圆级路线是 AI 芯片的重要分支，但更可能与 GPU 形成”分工”而非”取代”——GPU 做通用/训练，Cerebras 类做超低延迟推理或特定负载。

一句话总结：Cerebras 用面积、功耗和成本，换来了大模型推理中最稀缺的两样东西——带宽与低延迟。它的上限取决于能否把”最快”转化为”最常用”。
