Rust 初学者容易混淆的 20 个 Trait：用法、设计目的与边界

学习 Rust 时，最容易混淆的 trait 往往与语言机制直接相连：为什么整数赋值后还能使用，字符串却被移动？为什么 &String 可以传给接收 &str 的函数？为什么 move 闭包仍然可能实现 Fn？

本文选择 20 个常见 trait，从用法、设计目的和边界三个角度解释。理解它们的关键，是区分值本身、引用、底层数据和所有权，再明确每个 trait 向调用者承诺了什么。

阅读前的几个概念

Trait 定义类型应当提供的能力或满足的约定。impl Trait for Type 为类型实现这份约定，T: Trait 则要求泛型类型 T 满足它。有的 trait 定义方法，有的主要用于标记类型的性质，并与编译器规则配合。

&T 是共享引用，&mut T 是可变引用。移动转移值的所有权，借用通过引用访问值；复制或克隆是否产生独立的底层数据，需要结合具体类型判断。类型或 trait 中的关联类型（如 Iterator::Item）用来指定某个实现对应的输出等类型。

本文的“设计目的”讨论这些 trait 在语言中的职责。示例使用 Rust Edition 2021；被注释掉的错误用法用来说明约束，不属于可执行代码。

20 个 Trait 概览

Trait 核心问题 常见误解
Copy 能否安全地隐式复制值？ 赋值会自动调用 clone()
Clone 如何显式创建一个副本？ 一定会复制全部底层数据
Deref 如何像指针一样访问目标值？ 相当于继承或任意类型转换
Sized 类型大小能否在编译期确定？ String 长度可变，所以不是 Sized
From 如何从另一种类型构造这个类型？ 任何转换都适合实现 From
TryFrom 转换可能失败时如何报告错误？ 和 as 一样会截断数据
AsRef 如何低成本地提供另一类型的引用？ 任意 T 都自动实现 AsRef<T>
Borrow 如何提供语义一致的借用形式？ 与 AsRef 完全一样
ToOwned 如何从借用形式获得拥有形式？ 返回类型必须与原类型相同
Drop 如何在值销毁时执行资源清理？ 可以直接调用对象的 .drop()
Iterator 如何逐次产生元素？ map() 会立即遍历全部元素

FnOnce 如何允许一次调用消费闭包？ 实现 FnOnce 就意味着只能调用一次

1. Copy：允许隐式复制简单的值

let a = 42;
let b = a;
println!("{a}, {b}"); // i32 是 Copy，a 仍可用

let x = String::from("hello");
let y = x;
// println!("{x}"); // 编译错误：所有权已经移动给 y

Copy 是没有方法的标记 trait。它告诉编译器，这个类型可以通过复制自身的位表示，安全地得到另一个值。复制行为无法自定义，也不会调用 clone()。

移动和复制都可能在机器层面涉及内存拷贝，也都可能被优化掉；两者的关键区别是移动之后原绑定不能继续使用，而复制之后可以。

用法

#[derive(Debug, Copy, Clone)]
struct Point {
    x: i32,
    y: i32,
}

fn main() {
    let p1 = Point { x: 1, y: 2 };
    let p2 = p1;
    println!("{p1:?}, {p2:?}");
}

同时派生 Clone，因为 Copy 要求类型也实现 Clone。

设计目的与边界

让整数、坐标等简单值保持自然的使用体验，同时避免隐式复制需要特殊资源管理的对象。String 如果直接复制指针等字段，会让两个值负责释放同一块缓冲区，因此不能实现 Copy。

  • 结构体实现 Copy，要求所有字段都实现 Copy。
  • 实现 Drop 的类型不能实现 Copy。
  • 共享引用 &T 是 Copy，即使 T 不是；可变引用 &mut T 不是。
  • Copy 不保证复制成本可以忽略，大数组也可能是 Copy。
  • Copy 属于公开 API 的承诺，未来移除它会破坏依赖复制行为的调用代码。

来源：Rust 官方文档：Copy。

2. Clone：由类型定义显式复制行为

Clone::clone(&self) -> Self 借用原值，返回一个新值。它可以执行分配内存、增加引用计数等操作。

用法：String 的独立副本

fn main() {
    let mut a = String::from("Rust");
    let b = a.clone();

    a.push('!');
    assert_eq!(a, "Rust!");
    assert_eq!(b, "Rust");
}

这里 b 拥有独立的字符串缓冲区。

反例：Rc 克隆后仍共享数据

use std::rc::Rc;

fn main() {
    let a = Rc::new(String::from("Rust"));
    let b = Rc::clone(&a);

    assert!(Rc::ptr_eq(&a, &b));
}

Rc::clone 增加引用计数，产生另一个指向同一数据的句柄，没有复制底层字符串。Arc 也具有类似的共享语义。

设计目的与边界

不同类型需要不同的复制方式。显式的 clone() 让调用者看见这次操作，同时允许类型定义适合自己的复制机制。

普通结构体通常使用 #[derive(Clone)]，派生实现会逐个克隆字段。若字段包含 Rc 或 Arc，克隆后的结构体仍可能共享底层数据。

遇到所有权报错时，先判断函数是否只需要借用。只有确实需要另一个拥有所有权的值时，才考虑克隆。Clone 是否昂贵、是否共享数据，必须结合具体类型判断。

来源：Rust 官方文档：Clone。

3. Deref：让包装类型具有指针般的访问方式

Deref 的核心接口如下：

trait Deref {
    type Target: ?Sized;
    fn deref(&self) -> &Self::Target;
}

它返回目标值的共享引用，支持解引用操作，并参与解引用强制转换和方法查找。

用法

use std::ops::Deref;

struct MyBox<T>(T);

impl<T> Deref for MyBox<T> {
    type Target = T;

    fn deref(&self) -> &Self::Target {
        &self.0
    }
}

fn greet(name: &str) {
    println!("Hello, {name}");
}

fn main() {
    let name = MyBox(String::from("Rust"));
    greet(&name);
    println!("{}", name.len());
}

这里的 MyBox 仅演示包装与解引用，没有进行堆分配。

调用 greet(&name) 时发生引用转换：

&MyBox<String> → &String → &str

其中 String 实现了 Deref<Target = str>。这条路径借用同一份文本，不创建新的 String，不转移原字符串的所有权。

设计目的与边界

智能指针可以改变数据的存储或所有权方式，同时保留方便的目标值访问。例如 Box<T> 管理堆上的值，Rc<T> 管理共享所有权。

只有当包装类型应当透明地表现为目标类型、解引用成本低且行为符合预期时，才适合实现 Deref。不能仅因为 User 有一个 name: String 字段，就把它解引用为字符串；提供 name() 方法通常更清楚。

Deref 不建立继承关系，也不负责任意值转换。它提供共享访问，可变访问需要相应的 DerefMut。关联类型 Target 表达了这个实现对应的目标类型。

来源：Rust 官方文档：Deref。

4. Sized：约束类型本身的大小

Sized 表示类型的值具有编译期已知的固定大小。它描述值本身的表示，不计算值间接管理的全部堆数据。

类型 是否 Sized 原因
i32 是 大小固定
[i32; 3] 是 元素数量是类型的一部分
String 是 管理字符串的结构本身大小固定
str 否 文本数据长度不是固定的
[i32] 否 切片元素数量不是固定的
&str 是 引用及其元数据的表示大小固定

String 可以增长，但增长的是它管理的缓冲区，不是 String 值本身的大小。

用法：通过 ?Sized 放宽泛型约束

普通泛型类型参数默认带有 Sized 约束。因此，即使函数参数是 &T，T 也默认需要满足 Sized：

fn show<T: std::fmt::Debug>(value: &T) {
    println!("{value:?}");
}

放宽约束后，可以直接接受 str 和切片：

fn show<T: std::fmt::Debug + ?Sized>(value: &T) {
    println!("{value:?}");
}

fn main() {
    show("hello");         // T = str
    show(&[1, 2, 3][..]); // T = [i32]
    show(&42);            // T = i32，也可以
}

?Sized 表示取消必须为 Sized 的限制，允许两类类型；它不表示“必须大小未知”。

设计目的与边界

泛型默认具有容易处理的内存布局，需要支持动态大小类型时再显式放宽约束。对动态大小类型，通常通过引用、Box 等方式访问。

Sized 由编译器判断，不需要手动实现。trait 中隐含的 Self 是默认 Sized 规则的例外；否则就无法支持 trait 对象。

来源：Rust 官方文档：Sized。

5. From：统一可靠的类型转换

From<T> 用于从输入类型构造目标类型，接口是 fn from(value: T) -> Self。

用法

#[derive(Debug)]
struct UserName(String);

impl From<String> for UserName {
    fn from(value: String) -> Self {
        Self(value)
    }
}

fn main() {
    let a = UserName::from(String::from("Alice"));
    let b: UserName = String::from("Bob").into();
    println!("{a:?}, {b:?}");
}

这里将输入 String 移入包装类型，没有克隆字符串。

标准库提供通用实现，因此实现 From<A> for B 后，会自动获得 Into<B> for A。两者是同一个转换的不同调用方向：

let a = String::from("Rust");  // 从目标类型出发
let b: String = "Rust".into(); // 从来源值出发

实现转换时通常优先实现 From；泛型函数若希望接收多种能转成目标类型的输入，常使用 Into 约束：

fn make_name(value: impl Into<String>) -> String {
    value.into()
}

设计目的与边界

将转换纳入统一的 trait 协议，让构造、泛型 API 和错误转换能够协作。在返回 Result 的函数里，? 传播错误时也可以利用 From，将错误转成函数返回类型所需的错误类型。

From 表达的转换应当不会失败、保留有意义的信息，并且含义自然明确。如果构造 UserName 需要检查“不能为空”，应该考虑 TryFrom，而不是在 From 中对非法输入 panic。

From 按值接收的是输入类型 T。当 T 本身是引用时，传入的是引用，因此不能笼统地认为所有 From 转换都会取得底层数据的所有权。

来源：Rust 官方文档：From。

6. TryFrom：把可能失败的转换交给 Result

TryFrom<T> 的接口是 fn try_from(value: T) -> Result<Self, Self::Error>。与 From 相比，它多了关联类型 Error，明确允许转换失败。

用法

#[derive(Debug, PartialEq)]
struct Positive(i32);

impl TryFrom<i32> for Positive {
    type Error = &'static str;

    fn try_from(value: i32) -> Result<Self, Self::Error> {
        if value > 0 {
            Ok(Self(value))
        } else {
            Err("必须大于零")
        }
    }
}

fn main() {
    assert_eq!(Positive::try_from(3), Ok(Positive(3)));
    assert!(Positive::try_from(0).is_err());

    assert!(u8::try_from(300_u16).is_err());
    assert_eq!(300_u16 as u8, 44); // 整数窄化转换会截断
}

设计目的与边界

让“能否转换”成为类型化的结果，调用者可以传播、恢复或展示错误，而不必依赖 panic。适合整数范围缩小、受约束的新类型等场景。

实现 TryFrom<A> for B 后会自动获得 TryInto<B> for A。TryFrom 不表示每次都可能失败：已有 From 转换会通过标准库通用实现获得错误类型为 Infallible 的 TryFrom；不要再为同一对类型写冲突的实现。

示例使用 Edition 2021，该版本的 prelude 已包含 TryFrom、TryInto。把文本解析为数字常用 parse() 与 FromStr，不必把所有解析操作都包装为 TryFrom。

来源：Rust 官方文档：TryFrom。

7. AsRef：显式提供低成本的引用视图

AsRef<T>::as_ref(&self) -> &T 表达“我能廉价地提供一个 T 的共享引用”。它借用现有数据，不产生拥有所有权的新值。

用法

struct User {
    name: String,
}

impl AsRef<str> for User {
    fn as_ref(&self) -> &str {
        &self.name
    }
}

fn byte_len(value: impl AsRef<str>) -> usize {
    value.as_ref().len()
}

fn main() {
    assert_eq!(byte_len("Rust"), 4);
    assert_eq!(byte_len(String::from("Rust")), 4);
    let user = User { name: String::from("Alice") };
    assert_eq!(byte_len(&user), 5);
}

设计目的与边界

为函数统一接受不同输入提供接口，同时保留显式的 .as_ref() 调用。与 Deref 相比，它不会赋予包装类型相同的自动解引用行为；一个类型也可以实现多个目标类型的 AsRef。

这个例子允许从 User 取得姓名的引用，并不宣称整个用户与姓名具有同样的身份语义。

转换应低成本且不会失败。需要分配或校验时应选择其他接口。另外，标准库没有覆盖任意 T 的通用 AsRef<T> for T 实现，不能假设每个类型都自动支持引用自身。

例子中的 byte_len(String) 仍然会取得这个 String 的所有权，因为函数参数按值传入；AsRef 方法借用 self 并不决定外层函数如何接收参数。传入 &String 就能保留原值。

来源：Rust 官方文档：AsRef。

8. Borrow：借用形式必须保留键的比较语义

Borrow<Borrowed>::borrow(&self) -> &Borrowed 的签名看起来与 AsRef 相似，但它还有更强的语义要求：拥有形式与借用形式的相等、排序和哈希行为应一致。

用法：用 &str 查询 String 键

use std::collections::HashMap;

fn main() {
    let mut scores: HashMap<String, i32> = HashMap::new();
    scores.insert(String::from("Alice"), 90);

    assert_eq!(scores.get("Alice"), Some(&90));
}

String 实现了 Borrow<str>，所以查询时不必为了匹配键类型而分配临时 String。HashMap::get 使用查询形式的哈希与相等性去匹配存储的键。

设计目的与边界

让拥有值与它的借用表示能在泛型代码中作为同一逻辑值使用，尤其适合集合的异构查询。

例如某个自定义字符串类型按“不区分大小写”定义相等和哈希，就不能直接提供 Borrow<str>：普通 str 的比较与哈希区分大小写，两者不一致。若只想访问内部文本，可以实现 AsRef<str>。

不能仅因为结构体里存在一个字符串字段，就认为它适合实现 Borrow<str>。这些语义约定通常不是编译器能自动检查的。

来源：Rust 官方文档：Borrow。

9. ToOwned：从借用形式构造拥有形式

Clone 返回 Self，而 ToOwned 通过关联类型 Owned 返回对应的拥有形式，其接口是 fn to_owned(&self) -> Self::Owned，且 Owned: Borrow<Self>。

用法

fn main() {
    let text: &str = "Rust";
    let owned: String = text.to_owned();
    assert_eq!(owned, "Rust");

    let slice: &[i32] = &[1, 2, 3];
    let values: Vec<i32> = slice.to_owned();
    assert_eq!(values, vec![1, 2, 3]);
}

设计目的与边界

借用表示不一定能够直接作为拥有值使用，例如 str 与 [T] 是动态大小类型。ToOwned 把它们映射到 String 与 Vec<T>，并供 Cow 等抽象使用。

操作 典型输入 输出 含义
Clone::clone &String String 克隆同一类型
<&str as Clone>::clone &&str &str 克隆引用，仍共享文本
<str as ToOwned>::to_owned &str String 从文本视图构造拥有值
<[i32] as ToOwned>::to_owned &[i32] Vec<i32> 从切片构造拥有容器

标准库为 T: Clone 提供 ToOwned<Owned = T> 的通用实现，因此 String::to_owned() 也可用。ToOwned 并不保证所有底层数据都独立：对于包含共享指针的类型，仍应检查具体克隆语义。

来源：Rust 官方文档：ToOwned。

10. Drop：把资源清理绑定到值的生命周期

通常在值离开作用域时，Rust 会执行析构。实现 Drop::drop(&mut self) 可以加入自定义清理逻辑；随后字段也会由编译器生成的析构逻辑自动销毁。

用法

struct Guard(&'static str);

impl Drop for Guard {
    fn drop(&mut self) {
        println!("清理 {}", self.0);
    }
}

fn main() {
    let a = Guard("A");
    {
        let _b = Guard("B");
    } // 输出：清理 B

    std::mem::drop(a); // 输出：清理 A，提前结束其生命周期
    // a.drop();      // 禁止直接调用析构方法
    // println!("{}", a.0); // a 已经被移动给 drop
}

设计目的与边界

让内存、文件句柄和锁等资源跟随所有权生命周期清理，即 RAII。MutexGuard 离开作用域时释放锁，就是这种机制的常见用途。

大多数结构体不需要手写 Drop，字段会自动清理。std::mem::drop 是按值接收参数的普通函数，与 trait 的析构方法不同；drop(&value) 只丢弃一个引用，不销毁原值。

Drop 与 Copy 不能同时实现。析构不能作为“无论如何都会执行”的保证：主动遗忘值、直接终止进程等路径可以不执行析构。需要报告清理失败时，应提供显式返回 Result 的关闭方法，不能指望 drop() 返回错误。

来源：Rust 官方文档：Drop。

11. Iterator：把逐个产生元素变成统一协议

Iterator 的核心是关联类型 Item 与 fn next(&mut self) -> Option<Self::Item>。迭代器自身保存当前进度，调用 next() 推进状态。

用法：实现一个倒计数迭代器

struct Countdown(u8);

impl Iterator for Countdown {
    type Item = u8;

    fn next(&mut self) -> Option<Self::Item> {
        if self.0 == 0 {
            None
        } else {
            let value = self.0;
            self.0 -= 1;
            Some(value)
        }
    }
}

fn main() {
    let values: Vec<_> = Countdown(3).map(|n| n * 10).collect();
    assert_eq!(values, vec![30, 20, 10]);
}

设计目的与边界

让集合、生成器和其他数据来源使用同样的遍历协议，再通过 map、filter 等适配器组合处理步骤。这里 map 构造惰性适配器，collect 才驱动迭代并收集结果；构造源迭代器本身仍可能有其他成本。

Item 不必是引用，也可以是拥有值。迭代器通常会被推进，不会自动从头重来。

一般 Iterator 在返回一次 None 后，后续调用不一定永远返回 None；若需要这个保证，可以使用 .fuse()，或依赖 FusedIterator 约定。示例中的倒计数实现会一直返回 None。

来源：Rust 官方文档：Iterator。

12. IntoIterator：定义一个值怎样开始遍历

IntoIterator::into_iter(self) 将接收者转换成迭代器。它的关联类型 IntoIter 必须实现 Iterator<Item = Self::Item>。for 循环通过这个协议取得迭代器，再不断调用 next()。

用法：Vec 的三种遍历形式

fn main() {
    let mut words = vec![String::from("Rust")];

    for word in &words {       // Item = &String
        assert_eq!(word, "Rust");
    }

    for word in &mut words {   // Item = &mut String
        word.push('!');
    }

    for word in words {        // Item = String
        assert_eq!(word, "Rust!");
    }
    // println!("{words:?}"); // 容器已经被消费
}

设计目的与边界

区分“能够开始遍历的对象”和“保存遍历进度的迭代器”。集合可以从不同借用方式构造迭代器；迭代器则负责逐个输出元素。

Vec 上的调用 接收者类型 元素类型 原容器是否仍可使用
v.iter() &Vec<T> &T 借用结束后可以
v.iter_mut() &mut Vec<T> &mut T 借用结束后可以
v.into_iter() Vec<T> T 不可以，已被消费
(&v).into_iter() &Vec<T> &T 借用结束后可以

into_iter() 消费的是接收者 self；当 self 是引用时，消费的就是引用，而不是它指向的容器。不能只看方法名判断所有权。

标准库为所有 Iterator 提供了 IntoIterator 通用实现，转换后返回自身。因此自定义类型一旦实现 Iterator，就已经能用于 for，不要再写冲突的 IntoIterator 实现。

来源：Rust 官方文档：IntoIterator。

13. Send：值可以安全地跨线程转移

Send 是自动 trait，表达一个类型的值可以安全地跨越线程边界。通常由编译器根据字段类型自动判断，无需 derive 或手动实现。

用法

use std::thread;

fn assert_send<T: Send>() {}

fn main() {
    assert_send::<String>();
    assert_send::<std::cell::Cell<i32>>();

    let text = String::from("Rust");
    let worker = thread::spawn(move || text.len());
    assert_eq!(worker.join().unwrap(), 4);

    // assert_send::<std::rc::Rc<String>>(); // Rc 不是 Send
}

设计目的与边界

把跨线程转移的安全性写入类型系统，使线程 API 能拒绝不安全的数据传递。Rc 的引用计数不是原子操作，不能跨线程传递；Cell<i32> 可以转移到另一个线程，但不能凭共享引用让多个线程同时访问，因此它是 Send 而非 Sync。

move 只决定闭包如何捕获变量，不会绕过 Send。普通 thread::spawn 还要求闭包与返回值满足相关 Send、'static 约束；'static 与 Send 是不同要求，不表示线程永远运行。

手动实现 Send 需要 unsafe impl，相当于向编译器承诺线程安全条件成立，不能为了消除报错而随意添加。

来源：Rust 官方文档：Send。

14. Sync：共享引用可以安全地跨线程传递

Sync 也是自动 trait。它的精确定义是：T: Sync 当且仅当 &T: Send。因此关键不是值能不能转移，而是共享访问是否安全。

用法：通过 Mutex 保护共享修改

use std::sync::{Arc, Mutex};
use std::thread;

fn assert_sync<T: Sync>() {}

fn main() {
    assert_sync::<String>();
    assert_sync::<Mutex<i32>>();
    // assert_sync::<std::cell::Cell<i32>>(); // Cell 不是 Sync

    let counter = Arc::new(Mutex::new(0));
    let shared = Arc::clone(&counter);
    let worker = thread::spawn(move || {
        *shared.lock().unwrap() += 1;
    });
    worker.join().unwrap();
    assert_eq!(*counter.lock().unwrap(), 1);
}

设计目的与边界

让类型系统区分可以安全共享的内部可变性和没有同步保护的内部可变性。共享引用不一定只读：Mutex 允许通过共享引用获取锁后修改数据；Cell、RefCell 的内部可变性则没有提供跨线程同步。

类型 Send Sync 说明
String 是 是 可以转移，也可以共享借用
Cell<i32> 是 否 可转移，但不能跨线程共享访问
RefCell<i32> 是 否 运行时借用检查不提供线程同步
Rc<i32> 否 否 非原子引用计数
Arc<i32> 是 是 原子引用计数，内部 i32 也满足约束
Arc<RefCell<i32>> 否 否 Arc 不会替内部数据提供同步
Mutex<i32> 是 是 通过锁协调共享访问

Arc<T> 的 Send 与 Sync 实现要求 T: Send + Sync。它只解决共享所有权与引用计数安全，不会自动让内部类型线程安全。与 Send 一样，手动实现 Sync 也需要 unsafe impl。

来源：Rust 官方文档：Sync、Rust 官方文档：Send。

15. Unpin：不依赖 Pin 的固定地址保证

Unpin 是自动 trait，表示类型不依赖固定地址保证。对 T: Unpin，即使通过 Pin 包装的指针访问，也可以安全地取出普通可变引用、替换或移动目标值。

用法

use std::marker::PhantomPinned;
use std::pin::Pin;

struct AddressSensitive {
    _pin: PhantomPinned,
}

fn assert_unpin<T: Unpin>() {}

fn main() {
    assert_unpin::<String>();
    let mut text = String::from("Rust");
    {
        let pinned = Pin::new(&mut text);
        let normal: &mut String = pinned.get_mut();
        *normal = String::from("Rust!");
    }
    assert_eq!(text, "Rust!");

    let value = AddressSensitive { _pin: PhantomPinned };
    let moved = value; // 尚未固定，!Unpin 的值仍然可以移动
    let pinned = Box::pin(moved);
    let _moved_pointer = pinned; // 移动指针包装，不移动堆上的目标值
    // assert_unpin::<AddressSensitive>(); // PhantomPinned 阻止自动 Unpin
}

设计目的与边界

一些异步状态机或地址敏感的数据结构需要目标在固定之后保持地址稳定，但大多数普通类型并不需要这种保证。Unpin 让普通类型在需要 Pin 的接口中仍保持易用性。

!Unpin 不表示值从创建起就不能移动；只有建立固定保证之后，才必须遵守相应约束。Pin 固定的是指针指向的目标，通常不是指针包装本身。

PhantomPinned 只让包含它的类型不再自动实现 Unpin，不会自行建立固定保证，也不会自动验证自引用结构是否正确。示例只是演示类型约束，没有建立实际自引用。

异步中的 Future::poll 接收 Pin<&mut Self>，是遇见这些类型最常见的场景之一。不要用“所有 Future 都不能移动”概括：有的 future 是 Unpin，地址敏感的 future 在固定之前也可以移动。

来源：Rust 官方文档：Unpin。

16. Default：统一没有额外参数时的默认构造

Default::default() -> Self 为类型提供一个合理的默认值。它是普通的构造协议，不是“将内存全部设为零”，也不保证构造过程没有成本。

用法

#[derive(Debug, Default)]
struct Cache {
    entries: Vec<String>,
    enabled: bool,
}

#[derive(Debug)]
struct Options {
    timeout_secs: u64,
    retries: u32,
}

impl Default for Options {
    fn default() -> Self {
        Self { timeout_secs: 30, retries: 3 }
    }
}

fn main() {
    let cache = Cache::default();
    assert!(cache.entries.is_empty());
    assert!(!cache.enabled);

    let options = Options { retries: 5, ..Default::default() };
    assert_eq!(options.timeout_secs, 30);
    assert_eq!(options.retries, 5);

    let fallback: String = None.unwrap_or_default();
    assert!(fallback.is_empty());
}

设计目的与边界

给泛型代码和调用者一个统一的默认构造入口，支持配置项、空集合、可选值回退等场景。#[derive(Default)] 要求所有字段实现 Default，并逐个使用字段类型的默认值；业务默认超时为 30 秒时，就需要自己定义，而不是直接派生一个零值。

new() 是类型自己约定的关联函数，既可以带参数，也可以不带参数；它与 Default 没有自动对应关系。某个类型如果没有合理默认状态，不必为了方便而实现 Default。

结构体更新语法 ..Default::default() 使用默认实例补齐其余字段，但并不是向原实例上添加字段，也不承诺不会构造随后被替换的字段。枚举可以派生 Default，需要用 #[default] 指定一个无字段的默认变体。

来源：Rust 官方文档：Default。

17. Display：定义面向读者的文本表示

Display 用于 {} 格式化。实现 fn fmt(&self, f: &mut Formatter<'_>) -> fmt::Result 时，将文本写入格式化器，而不是自己向标准输出打印。

用法

use std::fmt;

#[derive(Debug)]
struct Coordinate {
    x: i32,
    y: i32,
}

impl fmt::Display for Coordinate {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(f, "({}, {})", self.x, self.y)
    }
}

fn main() {
    let point = Coordinate { x: 3, y: 4 };
    assert_eq!(format!("{point}"), "(3, 4)");
    assert_eq!(point.to_string(), "(3, 4)");
    assert_eq!(format!("{point:?}"), "Coordinate { x: 3, y: 4 }");
}

设计目的与边界

把对象的文本表示与输出目的地分离，让 println!、format! 和其他格式化调用共享同一实现。

Trait 格式符 常见用途 标准 derive 支持
Display {} 面向读者的文本 不支持
Debug {:?}、{:#?} 开发与调试表示 支持

实现 Display 后，标准库通用实现会提供 ToString，因此通常实现 Display，而不是手写 ToString。Display 不保证输出完整、无损或能解析回原对象，不能把它默认当作序列化协议。

fmt::Result 的错误表示格式化写入失败，不适合报告业务校验失败。如果同一类型需要多种展示形式，可以通过返回不同包装类型的展示适配器表达。

来源：Rust 官方文档：Display。

18. Fn：通过共享引用反复调用闭包

Fn 表达可调用对象能够通过共享引用调用。Fn(i32) -> i32 是泛型约束的常用写法，它与小写的函数指针类型 fn(i32) -> i32 不同。

用法：move 捕获不妨碍 Fn

fn call_twice<F: Fn() -> usize>(f: F) -> (usize, usize) {
    (f(), f())
}

fn main() {
    let text = String::from("Rust");
    let byte_len = move || text.len();
    assert_eq!(call_twice(&byte_len), (4, 4));
    assert_eq!(byte_len(), 4);

    let count = std::cell::Cell::new(0);
    let tick = || {
        count.set(count.get() + 1);
        count.get()
    };
    assert_eq!(call_twice(&tick), (1, 2));
}

第一个闭包拥有捕获的 String，但调用时只借用它，不修改或移出它，因此仍实现 Fn。第二个闭包通过 Cell 的内部可变性改变外部状态，也仍可通过共享引用调用。

设计目的与边界

让 API 能声明：“我需要反复调用这个对象，而且调用不需要独占其闭包环境。”闭包实现哪种调用 trait，由闭包体如何使用捕获值决定，不能只看有没有 move。

Fn 不表示纯函数：它仍可能打印、修改内部可变状态或操作外部资源；也不自动保证线程安全，并发共享还需判断 Sync 等条件。

实现 Fn 的类型也实现 FnMut 和 FnOnce。普通闭包的调用 trait 由编译器生成；稳定 Rust 中通常使用 f() 与这些泛型约束，不手动实现调用 trait 或直接调用底层 call 方法。

来源：Rust 官方文档：Fn、Rust Reference：Closure types。

19. FnMut：反复调用，并允许修改闭包环境

FnMut 表达可调用对象能够通过可变引用调用。它适合累计状态、推进计数、收集结果等需要多次执行的回调。

用法

fn call_twice<F: FnMut(i32) -> i32>(mut f: F, value: i32) -> (i32, i32) {
    (f(value), f(value))
}

fn main() {
    let mut total = 0;
    {
        let mut add = |n| {
            total += n;
            total
        };
        assert_eq!(call_twice(&mut add, 2), (2, 4));
        assert_eq!(add(1), 5);
    } // 闭包结束，释放对 total 的可变借用
    assert_eq!(total, 5);
}

函数参数上的 mut f 让函数内部能可变地借用闭包并反复调用。传入 &mut add 后，函数使用的是闭包的可变借用，因此返回后原闭包仍可调用。

设计目的与边界

在不消费闭包的前提下允许它更新捕获状态，适合迭代器适配器等需要反复执行的接口。例如 Iterator::map 接受 FnMut，所以映射过程可以维护累计状态。

Fn 可以用在需要 FnMut 的地方；只实现 FnMut 的闭包则不能直接满足 Fn 约束，因为调用它需要可变访问。

move 闭包也可能实现 FnMut：如果它拥有捕获的 Vec，每次调用仅执行 push 而不移出该 Vec，它可以继续调用。再次强调：捕获方式与调用时的使用方式是两个不同的问题。

来源：Rust 官方文档：FnMut、Rust Reference：Closure types。

20. FnOnce：允许调用消费闭包

FnOnce 的调用接收者按值传入。若一个 API 只要求 F: FnOnce()，它可以调用 f() 一次，不能在没有额外条件的情况下再次使用同一个 f。

用法：移出闭包拥有的 String

fn run_once<F: FnOnce() -> String>(f: F) -> String {
    f()
}

fn main() {
    let text = String::from("Rust");
    let take_text = move || text;
    assert_eq!(run_once(take_text), "Rust");
    // let again = take_text(); // 闭包已经被消费

    let greeting = || String::from("hello");
    assert_eq!(run_once(&greeting), "hello");
    assert_eq!(run_once(&greeting), "hello");
}

take_text 每次调用都需要把捕获的 String 移出环境，无法重复执行，因此只实现 FnOnce。greeting 不消费捕获值，实现 Fn，也就实现 FnOnce；通过共享引用传给 run_once，原闭包还可以继续使用。

设计目的与边界

让一次性回调可以移交捕获资源的所有权，并让只需调用一次的 API 接受尽可能广的闭包类型，例如 Option::unwrap_or_else 的回退函数。

实现 FnOnce 不等于“这个类型只能调用一次”。 Fn 与 FnMut 都继承 FnOnce。只有当已知条件仅为 FnOnce 时，调用者才能保证的能力是一次按值调用；具体类型可能还支持更强的调用方式。

三种闭包调用约束如何选择

下表的接收者是调用协议的概念示意，正常代码使用 f()，不直接调用底层方法。

Trait 概念上的调用接收者 API 能依赖的调用能力 典型捕获值使用方式
Fn &self 通过共享引用重复调用 读取捕获值，也可用内部可变性
FnMut &mut self 通过可变引用重复调用 修改捕获环境，不移出不可复制的捕获值
FnOnce self 按值调用一次 可以移出捕获的资源

实现关系是 Fn ⇒ FnMut ⇒ FnOnce：只调用一次通常要求 FnOnce；多次调用且允许修改环境通常要求 FnMut；需要共享引用调用才要求 Fn。不要把三者当作互不相交的闭包类别。

来源：Rust 官方文档：FnOnce、Rust 官方文档：FnMut、Rust 官方文档：Fn。

用同一个 String 串起前五个概念

let s = String::from("Rust");

// let moved = s;           // 移动 String，之后不能继续使用 s
let cloned = s.clone();    // Clone：创建独立的 String
let borrowed: &str = &s;   // Deref：借用字符串内容
let another = borrowed;   // Copy：复制 &str，不复制文本
let owned = String::from(borrowed); // From：创建拥有数据的 String

s 是 Sized，borrowed 的类型 &str 也是 Sized，但它指向的 str 不是。

判断 API 时可以依次问：需要借用还是拥有？需要副本还是共享句柄？包装类型是否应透明暴露目标？泛型是否需要接受动态大小类型？转换是否可能失败？这些问题对应前五个 trait 的职责。

相似接口的选择

需求 优先考虑 判断依据
简单值应当能被隐式复制 Copy 位复制安全，且隐式复制符合类型语义
显式创建同类型副本 Clone 具体类型决定是否分配、是否共享数据
从借用形式获得拥有形式 ToOwned 输出类型可能不同，如 str → String
获取低成本引用视图 AsRef 只承诺引用转换
提供用于集合查询的借用形式 Borrow 比较、排序与哈希语义一致
包装类型应透明表现为目标类型 Deref 接受自动解引用成为公开 API
无失败且含义明确的转换 From 实现后自动获得 Into
可能失败的转换 TryFrom 通过 Result 报告错误
自定义资源清理 Drop 资源清理跟随所有权生命周期
泛型需要支持 str、切片等 ?Sized 放宽 Sized 限制，而不是要求大小未知
定义逐步产出元素的状态机 Iterator next 推进状态
定义集合或引用如何开始遍历 IntoIterator self 的类型决定消费还是借用
将值安全地传到其他线程 Send 与共享访问、生命周期约束分别判断
将共享引用安全地传到其他线程 Sync T: Sync 等价于 &T: Send
判断固定之后能否自由移动目标 Unpin 类型是否依赖固定地址保证
提供合理的无参默认构造 Default 业务默认值不一定等于字段默认值
定义面向读者的文本表示 Display 使用 {}，自动获得 ToString
回调需要通过共享引用重复调用 Fn 不等于纯函数或线程安全
回调需要多次调用且允许修改环境 FnMut 调用者需要可变访问闭包
回调只需按值调用一次 FnOnce 允许捕获资源在调用时被消费

建议按“复制与拥有 → 转换与借用 → 清理与迭代 → 线程安全 → 固定地址 → 默认值与格式化 → 闭包调用”的顺序学习。重点不是背接口名称，而是看清接收者类型、返回类型、所有权变化和语义约定。
