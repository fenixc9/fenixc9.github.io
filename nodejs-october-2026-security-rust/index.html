Node.js 十月安全发布剖析：C 的内存不安全、JS 的校验裸奔，为什么该把关键组件交给 Rust

4.3k 字 36 分钟

Node.js 十月安全发布剖析：C 的内存不安全、JS 的校验裸奔，为什么该把关键组件交给 Rust

Node.js 在 2026 年 10 月 21 日一次性修复了 10 个漏洞，覆盖 22.x、24.x、26.x 三条仍在维护的发布线。把每个 CVE 按缺陷所在的代码层拆开看，会得到一个很朴素的结论：能远程执行代码的那个，来自 C 写成的 Brotli 解码器；而看起来”蠢得可怕”的绕过与截断，几乎都长在 JavaScript 胶水层的输入校验上。 前者是内存不安全，后者是校验缺失——这两类问题恰好对应两种不同的治理手段，也解释了为什么把关键组件迁到 Rust 不是跟风，而是一笔可以算清楚的账。

本文事实来源为 Node.js 官方安全发布公告、各版本 release note，以及 Chromium、Google Android 团队公开的内存安全数据，资料核对时间为 2026 年 10 月 21 日。

一、这次发布到底修了什么

官方公告列出的修复覆盖 10 个漏洞：4 个高危、3 个中危、3 个低危。修复版本为 v22.23.4（LTS）、v24.22.1（LTS）、v26.12.1（Current）；End-of-Life 版本不出补丁，按官方说法”始终受影响”。

严重度 CVE 问题
高危 CVE-2026-111497 Brotli 解码器越界写，可远程执行代码
高危 CVE-2026-106069 主机名松散解析为 IP 时绕过 TLS 证书校验
高危 CVE-2026-105483 IP 写成全角数字时绕过 TLS 证书主机名校验
高危 CVE-2026-105482 dns.resolve 截断含 NUL 字符的名称
中危 CVE-2026-105481 keep-alive socket 处理了请求发出之前写入的响应
中危 CVE-2026-106072 非规范 IPv4 主机名的证书校验缺陷，DNS SAN 可认证 IP 端点
中危 CVE-2026-106074 crypto.randomUUID()/randomInt() 的熵缓存进入启动快照与 SEA，进程间重复同一组随机值
低危 CVE-2026-106070 ZIP 头校验失败后返回攻击者可控的前缀字节（仅 26.x）
低危 CVE-2026-106071 Permission Model 通配符 radix 查找导致文件系统过度授权（仅 26.x）
低危 CVE-2026-106073 fs.realpathSync 绕过 Permission Model

除了自身代码，这次发布还捆绑了一批依赖更新：c-ares、OpenSSL、SQLite、Undici，以及 ca-cert。其中 ca-cert 更新对应的是同一周爆出的 eMudhra 中间 CA 私钥弱随机事件——Node.js 自带的根证书库同步移除了问题根。一个版本升级，两件事一起解决。

二、按语言归因：可怕的在 C，蠢的在 JS 边界

Node.js 仓库的语言构成大致是 JavaScript 66%、C++ 23%、C 2%（按 GitHub 统计的字节数，不含以 npm 形式引入的主题源码）。但这个比例有严重的误导性：真正处理不可信字节的那些组件——V8、OpenSSL、c-ares、Brotli、llhttp——几乎全部是 C/C++，JavaScript 只是调用它们的那一层。

把这次的 10 个漏洞按代码层摊开：

CVE 缺陷所在层 缺陷性质
111497 Brotli 越界写 C（Brotli 解码库） 内存不安全
105482 NUL 截断 C（c-ares 字符串）× JS 传参边界 内存模型不匹配
105483 全角数字绕过 JS 主机名校验 × OpenSSL 绑定 输入未归一化
106069 松散解析绕过 JS 校验逻辑 输入未归一化
106072 非规范 IPv4 JS 校验逻辑 输入未归一化
105481 keep-alive 时序 JS（HTTP agent） 状态机逻辑错误
106074 熵缓存进快照 V8（C++）快照 × JS 层缓存 语义假设错误
106070 ZIP 前缀字节 解析边界 校验顺序错误
106071/106073 Permission Model JS 路径判定逻辑错误

规律相当干净：唯一具备”远程执行代码”能力的漏洞，是 C 的越界写；其余那些让人皱眉的绕过，全是”字符串比对之前没有把输入归一化成规范形式”。

全角数字那个尤其典型。１９２．１６８．１．１ 在视觉上就是 192.168.1.1，但它是另一串 Unicode 码点。如果主机名校验把”待校验的名字”和”证书里的名字”都当普通字符串比较，中间没有强制解析成 IP 类型，这类输入就会从两条不同路径通过检查，然后落到两个不同结论上。

三、两类缺陷，两种解法

这两类问题的根本差别在于：内存不安全是语言允许的，校验缺失是设计遗漏的。 前者的解药是换语言，后者的解药是换输入模型。

维度 内存不安全（越界写、UAF、double free） 校验缺失（未归一化、路径判定、状态机）
典型后果 崩溃、信息泄露、远程执行代码 绕过认证、证书冒充、权限逃逸
能否被编译器拦截 换内存安全语言即可基本消除 编译器只能帮一部分，要靠类型设计
修复成本 事后打补丁永远打不完 一处修好即可，但容易在新代码重现
历史占比 高危漏洞的绝大多数 少数但更”难看”

这也解释了为什么”换语言”这件事听起来像政治正确，实际上是有硬数据的。Chromium 项目统计了 2015 年以来 912 个高危和严重级别安全缺陷，结论是约 70% 属于内存不安全问题；微软 MSRC 的同类统计也长期在 70% 上下。而 Android 团队把新代码逐步换成内存安全语言之后，内存安全漏洞在该平台全部漏洞中的占比，从 2019 年的 76% 降到了 2024 年的 24%。

真正起作用的是新代码：存量 C/C++ 不会自己变安全，但只要不再往里面加新的不安全代码，这个比例就会持续下降。Android 的曲线本质上就是”新增代码全用内存安全语言”的复利。

四、Rust 能解决哪一半，不能解决哪一半

必须把话说清楚，否则迁移就变成了信仰。

Rust 能消掉的： 越界读写、释放后使用、双重释放、数据竞争。这类问题在安全 Rust 里基本不可能写出来，所有权与借用检查在编译期就拒绝。需要 unsafe 的地方是显式、可枚举、可审计的，而不是散落在整个代码库里。也就是说，CVE-2026-111497 这种”解码器越界写导致 RCE”的漏洞，在 Rust 实现里第一道防线就是编译失败。

Rust 能顺带改善的： 这次一半的”蠢”漏洞都和”把输入当裸字符串处理”有关，而 Rust 的类型系统天然鼓励”尽早解析成有意义的类型”。用 std::net::IpAddr 解析全角数字会直接失败；str 与 [u8] 的区分逼着你在边界上想清楚编码；没有 NUL 结尾字符串的默认约定，dns.resolve 那种”传进去被截断”的类 C 语义不会自然出现。这不是说 Rust 让逻辑 bug 消失，而是它让你想犯这类错误时需要多写几行、并且在编译期被问一次”你真的确定这个字符串是 IP 吗”。

Rust 不能解决的： CVE-2026-105481 那种状态机时序错误、Permission Model 的路径判定绕过（fs.realpathSync 与通配符匹配的先后顺序），换成任何语言都照样会犯。这类问题的解药是威胁建模、路径规范化后再判定的固定顺序，以及针对权限边界的模糊测试。

所以准确的表述是：Rust 消灭的是”最严重的那个类别”，不是”所有 bug”。

五、给客户与团队的建议：从不可信输入的高权限路径开始

如果真的要把这件事落地，别从”重写整个服务”开始，那一定失败。按风险排序、按组件边界替换，是唯一现实的路径。

第一步：画出你的不可信输入清单。 谁在解析外部字节？HTTP 解析器、压缩与解压、TLS、DNS、序列化协议、文件格式（ZIP、图片、PDF）、模板引擎。这些组件同时具备”吃攻击者可控数据”和”运行在高权限上下文”两个特征，是优先项。

第二步：逐组件替换，而不是逐服务重写。 Node.js 生态里这件事已经发生了一半——SWC、Oxc、Biome、Rspack、Rolldown、Turbopack 这些取代 Babel/Terser/Webpack 位置的工具全是 Rust 写的；Deno 的核心是 Rust；连 Node.js 自带的 Corepack 也是 Rust。TLS 侧 rustls 已经是 curl 和 Hyper 可选的成熟后端。你的团队多半已经通过依赖间接运行了大量 Rust 代码，只是没有意识到。

第三步：用 FFI 缝合，而不是一次跨语言重写。 Node 侧用 napi-rs 或 neon 暴露 Rust 实现，保持 JS 侧调用签名不变，内部替换。这样每一步都可以独立灰度和回滚。

第四步：接受迁移的真实成本。 Rust 的学习曲线、借用检查带来的设计返工、与现有 C 库的 FFI 边界（边界本身仍需 unsafe）、以及生态成熟度差异，都是真金白银。对只有几个人的团队，”把所有东西重写成 Rust”是不理智的；但”把那个吃外部压缩包的解析器换掉”通常是几周的事。

顺带一提，这次发布里的 crypto.randomUUID() 熵缓存问题，和同一周印度 CA 的弱随机数事件是同一类病：随机性上的假设一旦错了，后果往往是”所有进程共享同一个种子”这种系统级灾难，而不是单个请求出错。 密码学代码里，”这段逻辑看起来对”从来不是足够的证据。

六、结论

这次 Node.js 的 10 个漏洞其实是一次很好的教材：一个 C 的越界写就能换到远程执行代码，而 JS 层那堆看着可笑的全角数字和 NUL 截断，本质上都是”没在边界上把输入变成规范类型”。

对个人用户，行动很简单：升级到 v22.23.4 / v24.22.1 / v26.12.1 或更高版本，一次升级同时解决这些 CVE 和 eMudhra 根证书的信任问题。

对团队与客户，建议也很简单：不要指望用补丁把 C 的内存不安全补完，那是无底洞；把解析不可信输入的那些组件逐步换成 Rust，把剩下的精力留给真正需要人判断的校验与状态机设计。 语言选型从来不是审美问题，它是把哪一类 bug 变成”写不出来”的问题。
